# 植株订单售后归因演示

纯 Node.js 内置模块的本地网页 demo：订单替换前后保留植株品类，售后投诉工单可先挂父订单、再由归因模块（给出候选订单行 + 可信度）改挂到某一件；指标端分开统计**替补使用率**与**投诉率**，未认领 / 未定位的个案单列边界，不计入投诉率。

## 运行

```bash
node server.js        # 读取 PORT 环境变量，默认 3000，绑定 127.0.0.1
PORT=8080 node server.js
```

打开 http://127.0.0.1:3000 ，页面提供三个操作：

- **计算原替换和投诉**：按当前数据计算各品类替补使用率与投诉率，并列出边界个案；
- **重分配一张投诉单**：把选中的投诉单改挂到某一行（留空则按可信度自动归因，低于阈值 0.6 拒绝并保持边界单列），返回处理前后对比——哪个品类投诉数变化、已认领投诉总数不变（未重复计算）；
- **查看品类归因**：每张投诉单的候选订单行、可信度与是否计入指标。

业务结果区是 `<section id="evidence" data-evidence-result="...">`，属性值随操作变化（`idle / compute / reassign / attribution / reset / error`），方便核对操作前后内容。

## 虚构数据

- 3 张订单共 6 行，其中 2 行发生替补：绣球→月季、兰花→绿萝（替换前后品类都保留在行上）；
- 4 张工单：T9001 投诉（已认领，先挂父订单）、T9002 投诉（已认领，已挂多肉行）、T9003 投诉（未认领，边界个案）、T9004 咨询（非投诉，不进指标）。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 当前订单与工单 |
| POST | `/api/compute` | 计算替补使用率 / 投诉率 / 边界清单 |
| POST | `/api/reassign` | body `{ticketId, lineId?}`，重分配一张投诉单 |
| GET | `/api/attribution` | 品类归因视图（候选行 + 可信度） |
| POST | `/api/reset` | 重置为初始虚构数据 |

## 测试

```bash
node --test
```

覆盖正常路径（指标计算、归因可信度、重分配后品类变化且总数守恒）与异常路径（工单不存在、非投诉单、订单行不存在 / 不属于父订单、自动归因可信度不足、非法 JSON、未知路径 404）。
